02 — Điểm Mạnh

Những Gì Đang Hoạt Động Tốt

11 điểm mạnh cốt lõi tạo nền tảng vững chắc cho hệ thống — cần bảo tồn và không phá vỡ trong quá trình cải tiến.

Kiến trúc App Router nhất quán

Next.js 13.5 App Router với service layer tách biệt rõ ràng — 90+ service files, mỗi file có JSDoc và return type tường minh.

RBAC chi tiết & mở rộng được

20 module mẹ + 25 module con, 7 loại action (view/create/edit/delete/approve/export/admin). Ma trận phân quyền có thể sửa từ DB.

Design system dark-mode-first

CSS variables nhất quán, không hardcode màu sắc, dễ theming. Tất cả component dùng var(--card), var(--fg), border rgba.

Multi-company support đầy đủ

Company switcher trên Topbar, getEffectiveContext() tự suy role theo công ty hiện tại — 1 user nhiều vai trò ở nhiều công ty.

Tích hợp Zimbra SOAP sâu

Tạo/xóa email, đẩy chữ ký HTML, quản lý tài khoản qua Admin API. Hỗ trợ TLS với tuỳ chọn bỏ qua cert check cho môi trường internal.

Realtime qua Server-Sent Events

SSE cho attendance và notifications — nhẹ hơn WebSocket, không cần thư viện bổ sung, hoạt động tốt qua Traefik/Docker.

167 migration idempotent

Dùng IF NOT EXISTS — migration có thể chạy lại không lỗi. Quy trình chặt chẽ: cột mới = migration ngay, không để nợ kỹ thuật.

ATS đầy đủ pipeline tuyển dụng

Kanban @dnd-kit, trích xuất CV (pdf-parse + mammoth), kho JD, pipeline từ yêu cầu → duyệt → ứng viên → onboarding.

Export Excel chuẩn bảng công VN

Format DETAIL_fill với xlsx-js-style, tab Chế Độ & Đãi Ngộ, phân biệt công đặc biệt (công tác / WFH / làm theo ca).

Telegram integration đôi chiều

Login widget xác thực HMAC + approval bot cho workflow duyệt yêu cầu ngay trên Telegram — giảm thời gian xử lý đáng kể.

282 API endpoints — phủ sóng toàn bộ nghiệp vụ

Pattern chuẩn với try/catch, error logging, permission check trên mọi route. Tách biệt collection route (/api/x) và item route (/api/x/[id]) nhất quán.

03 — Vấn Đề UI/UX

Các Vấn Đề Được Phát Hiện

8 vấn đề phân theo mức độ ảnh hưởng — từ bảo mật nghiêm trọng đến cải thiện trải nghiệm nhỏ.

Mức độ Khu vực Vấn đề Đề xuất xử lý
HIGH API Security
Permission check có thể bị giả mạo
checkPermission() đọc quyền từ header x-user-permissions do client tự gửi — bất kỳ ai cũng có thể spoof header này để leo thang quyền.
 Thay thế bằng session/JWT verify phía server. Đọc quyền từ DB theo session token, không từ header client. Ưu tiên khẩn cấp trước khi mở public.
HIGH Chấm Công / IA
Tính năng cốt lõi bị chôn sâu trong Tra Cứu
Cấu trúc /tra-cuu/du-lieu-cong đặt chức năng chấm công (nghiệp vụ chủ lực hàng ngày) bên trong module Tra Cứu — làm giảm tầm quan trọng và tăng độ sâu breadcrumb không cần thiết.
 Tách thành top-level route /cham-cong với 4 tab: Checkin, Tra Cứu, Máy ZKTeco, Cấu Hình Nghỉ Phép. Giảm breadcrumb từ 3 cấp xuống 2 cấp.
MEDIUM URL Convention
URL slug không nhất quán tiếng Anh / tiếng Việt
Mix không đồng đều: /tra-cuu, /nguon-nhan-luc, /duyet-yeu-cau (tiếng Việt) lẫn với /asset-management, /tickets, /tasks (tiếng Anh). Gây khó bookmark và không thân thiện SEO.
 Chọn một quy ước duy nhất — ưu tiên tiếng Anh cho slug. Ví dụ: /lookup, /hr, /approvals, /attendance. Có thể thêm redirect 301 từ URL cũ.
MEDIUM Sidebar / IA
Module delete-requests và duyet-yeu-cau chồng lấp
Hai điểm vào khác nhau cho nghiệp vụ tương tự: /delete-requests (duyệt xóa tài sản) và /duyet-yeu-cau (bù công, tăng ca, xóa tài sản). Người dùng tìm kiếm ở 2 chỗ.
 Gộp vào /approvals duy nhất với tab con: Bù Công / Tăng Ca / Xóa Tài Sản / Bảng Công. Giảm cognitive load khi cần duyệt yêu cầu.
MEDIUM Code Reuse
Ticket và Task có UI tương tự nhưng component riêng biệt
Cả hai module đều có detail modal, comment thread, attachment, follower — nhưng được implement hoàn toàn riêng rẽ. Bảo trì tốn gấp đôi chi phí khi cần thay đổi.
 Tạo shared component DetailPanel, CommentThread, AttachmentList, FollowerPicker có thể nhận props cấu hình. Giảm ~40% code duplicate.
MEDIUM Onboarding Route
Hai route onboarding dễ nhầm lẫn public vs private
/nguon-nhan-luc/onboarding (HR quản lý, cần đăng nhập) và /onboarding/thong-tin-nhan-su-dau-vao (public form điền thông tin) gần giống nhau — dễ share nhầm link cho nhân sự mới.
 Đặt public form vào /forms/onboarding/[token] để tách bạch hoàn toàn. Public route không cần auth, private route trong /hr/onboarding.
LOW Màu Module
Modules announcements và recruitment-order dùng cùng màu
Cả hai module dùng #F97316 trong permission matrix — gây khó phân biệt trực quan khi admin cấu hình quyền cho nhiều module HR cùng lúc.
 Gán bảng màu phân biệt: announcements → amber, recruitment → teal/cyan, offboarding → slate. Tổng cần 20 màu riêng biệt cho 20 module mẹ.
LOW Empty State
Mỗi trang tự implement empty state riêng
Theo CLAUDE.md template, mỗi trang có empty state riêng — thiếu nhất quán về icon size, text style, spacing giữa các trang khác nhau trong cùng hệ thống.
 Tạo shared EmptyState component với props: icon, title, description, action?: {'{label, onClick}'}. Import từ components/ui/EmptyState.tsx.

05 — Đề Xuất Ưu Tiên

Cải Tiến Theo Thứ Tự Ưu Tiên

6 cải tiến xếp theo tác động thực tế — từ bảo mật khẩn cấp đến tối ưu trải nghiệm dài hạn.

01

Thay thế permission check giả mạo được bằng session verify thực

Đây là lỗ hổng bảo mật nghiêm trọng nhất. Bất kỳ người dùng nào cũng có thể tự set header x-user-permissions để leo thang quyền truy cập. Cần implement JWT hoặc server-side session store (Redis/DB), xác thực mọi request API từ token — không tin tưởng input từ client.

Khẩn cấp
Tác động bảo mật
Effort: Cao
02

Tách Chấm Công thành top-level route /cham-cong

Chấm công là nghiệp vụ hàng ngày của mọi nhân viên và quản lý — không nên chôn trong /tra-cuu. Tách ra /cham-cong với 4 tab sẽ giảm breadcrumb từ 3 cấp xuống 2 cấp, người dùng tìm thấy nhanh hơn. Đây là thay đổi IA có tác động người dùng lớn nhất.

HIGH
Tác động UX
Effort: Thấp
03

Gộp delete-requests và duyet-yeu-cau thành /approvals

Hai module chồng lấp gây confusion — người phê duyệt phải nhớ 2 chỗ khác nhau. Gộp thành /approvals với tab Bù Công / Tăng Ca / Xóa Tài Sản / Bảng Công. Thêm badge số lượng pending trên sidebar item để thay thế cả hai mục hiện tại.

MEDIUM
Tác động UX
Effort: Thấp
04

Chuẩn hóa URL slug sang tiếng Anh toàn bộ

Định ra convention: tất cả route slug dùng tiếng Anh viết thường, dấu gạch ngang. Mapping đề xuất: /tra-cuu → /lookup, /nguon-nhan-luc → /hr, /duyet-yeu-cau → /approvals, /nhan-su → /users, /bieu-mau → /forms, /ho-so-cua-toi → /my-profile. Thêm redirect 301 để không phá bookmark cũ.

MEDIUM
Tác động DX
Effort: Trung bình
05

Tạo shared DetailPanel và CommentThread component

Ticket và Task share ~60% UI logic (header, status badge, comment thread, attachment list, follower picker, timeline). Tạo shared component trong components/shared/ với render props hoặc composition pattern. Giảm maintenance burden khi cần thêm tính năng cho cả hai module (ví dụ: reaction, mention).

MEDIUM
Tác động DX
Effort: Trung bình
06

Shared EmptyState component và màu module phân biệt

Tạo EmptyState component tái sử dụng với props chuẩn, thay thế các implementation riêng trên từng trang. Song song đó, gán 20 màu phân biệt cho 20 module trong permission matrix — ưu tiên nhóm HR có nhiều module dễ nhầm lẫn nhất (announcements, recruitment, onboarding, offboarding).

LOW
Tác động UX
Effort: Thấp
