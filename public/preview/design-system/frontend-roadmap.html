Điểm mạnh

Hệ thống có nền kiến trúc vững chắc với App Router nhất quán, RBAC chi tiết và design system dark-mode-first. Điểm yếu chính tập trung ở bảo mật API (permission spoofing), cấu trúc URL không nhất quán, và component duplication giữa Ticket/Task. Không có blocker production ngay lập tức nhưng cần giải quyết debt bảo mật trước khi mở public access.

Ưu tiên tuyệt đối: Vá lỗ hổng permission spoofing trước Sprint 2 — đây là rủi ro bảo mật critical ảnh hưởng toàn bộ 282 API endpoints.

Top 5 Cải Tiến Ưu Tiên

  • 🔴

    Server-side Permission Verification

    Thay thế header-based permission check bằng JWT/session verify — ngăn chặn privilege escalation toàn hệ thống

  • 🟠

    Tách Chấm Công thành Top-level Route

    Di chuyển /tra-cuu/du-lieu-cong → /cham-cong, tăng discoverability và giảm breadcrumb depth

  • 🟠

    URL Slug Chuẩn hóa sang Tiếng Anh

    Thống nhất tất cả route sang kebab-case tiếng Anh (SEO-friendly, bookmark-safe, copy-paste không bị encode)

  • 🔵

    Shared DetailPanel / CommentThread Component

    Tái sử dụng UI Ticket/Task — giảm 40%+ code duplication, đảm bảo behavior nhất quán

  • 🔵

    Thống nhất Auth System (DB + bcrypt only)

    Xóa MOCK_USERS authStore.ts, giữ luồng /api/auth/login duy nhất — loại bỏ dual auth paradox

02 / 08

Vấn Đề Nhất Quán Hiện Tại

HIGH Chấm Công bị chôn vùi trong /tra-cuu

Module chấm công là chức năng hàng ngày của toàn bộ nhân viên nhưng đặt sâu trong "Tra Cứu" — breadcrumb 3 cấp, người dùng mới khó tìm, sidebar không reflect đúng tầm quan trọng.

Fix: Tạo top-level route /attendance (hoặc /cham-cong), thêm vào nhóm HOẠT ĐỘNG trong sidebar, redirect từ URL cũ
HIGH Empty State không nhất quán toàn hệ thống

Mỗi trang tự implement empty state riêng theo template CLAUDE.md — không có shared component → inconsistent icon, text style, action button. Ước tính 22+ trang bị ảnh hưởng.

Fix: Tạo components/ui/EmptyState.tsx với props: icon, title, description, action (label + onClick)
MEDIUM URL mixing: tiếng Việt + tiếng Anh

Ví dụ: /tra-cuu, /nguon-nhan-luc, /duyet-yeu-cau (tiếng Việt) vs /asset-management, /tickets, /tasks (tiếng Anh). URL tiếng Việt bị percent-encode thành %2F%74%72%61... khi copy.

Fix: Chuẩn hóa toàn bộ sang kebab-case tiếng Anh. Thêm redirect 308 từ URL cũ. Ưu tiên tiếng Anh vì SEO + bookmark-safe.
MEDIUM delete-requests vs duyet-yeu-cau — chức năng chồng lấp

Hai entry point khác nhau cho cùng workflow duyệt xóa tài sản — người dùng không biết nên dùng cái nào, data phân tán, breadcrumb không thống nhất.

Fix: Gộp về /approval-requests với tab con: "Xóa Tài Sản" | "Yêu Cầu Khác". Xóa một trong hai route, redirect về route gộp.
MEDIUM Onboarding route nhầm lẫn: HR vs Public

/nguon-nhan-luc/onboarding (authenticated HR) và /onboarding/thong-tin-nhan-su-dau-vao (public form) dùng cùng tên — dễ nhầm trong analytics, link sharing, và routing logic.

Fix: Đổi public form → /forms/onboarding hoặc /forms/[token]. HR management giữ nguyên trong /hr/onboarding.
LOW Module color collision: announcements vs recruitment-order

Cả hai module dùng #F97316 trong permission matrix — visual fingerprint bị trùng, khó phân biệt trong dashboard và audit logs.

Fix: Gán màu duy nhất theo nhóm: HR group dùng palette teal/emerald, Operations dùng orange/amber, Admin dùng purple/violet.

Multi-tenant Architecture

✓ Đã có: Company switcher + getEffectiveContext
Multi-company membership (migration 149) đã hoạt động tốt
⚠ Cần: Row-level isolation thực sự
RLS policy hiện là USING(true) — mọi query cần thêm WHERE company_id = $current để data isolation
→ Kế hoạch: CompanyContext middleware
Middleware tự động inject company_id vào mọi DB query thông qua withCompanyContext() helper

Service Layer Separation

✓ Điểm mạnh: 90+ service files
Business logic tách biệt khỏi API route — dễ test, dễ tái sử dụng trong scheduler
⚠ Cần: Service interfaces (contracts)
Khai báo interface IUserService, IAssetService — giúp mock trong test và swap implementation
→ Error handling chuẩn hóa
Tạo ServiceError class với code, message, statusCode — API route chỉ cần catch và forward

API Caching Strategy

Giai đoạn 1: SWR client-side
useSWR với stale-while-revalidate cho list endpoints ổn định (modules, permissions, users)
Giai đoạn 2: Next.js Route Handlers cache
revalidate: 300 cho static data endpoints — giảm DB load ~60%
Giai đoạn 3: Redis (khi scale)
Shared cache giữa Docker containers, session store, rate limiting

Technical Debt

06 / 08
CRITICAL Permission Spoofing

checkPermission() đọc quyền từ header x-user-permissions do client gửi. Bất kỳ ai cũng có thể curl với header giả để truy cập admin API endpoints. Ảnh hưởng 282 endpoints.

Kế hoạch sửa
  • Tạo bảng sessions (token, user_id, expires_at, company_id)
  • Middleware Next.js đọc cookie httpOnly, verify token từ DB
  • Inject user context vào request.headers nội bộ (server-only)
  • Deprecate x-user-permissions header hoàn toàn
  • Estimate: 2-3 sprint nếu làm cẩn thận
HIGH Dual Auth Systems

Hai hệ thống auth song song: DB + bcrypt (đúng, an toàn) và authStore.ts + MOCK_USERS (so sánh plaintext client-side — cực kỳ nguy hiểm). Risk: user có thể bypass DB auth.

Kế hoạch sửa
  • Audit tất cả import của authStore.ts (grep toàn repo)
  • Migrate từng consumer sang /api/auth/login flow
  • Delete src/lib/authStore.ts khi không còn import nào
  • Thêm ESLint rule ban import từ authStore
MEDIUM Migration Numbering Conflicts

Hai file cùng số 008, 009, 012 — thứ tự chạy không xác định khi init DB mới từ scratch. Có thể gây lỗi ALTER TABLE khi cột chưa tồn tại hoặc đã tồn tại.

Kế hoạch sửa
  • Audit đầy đủ tất cả file migration hiện tại (167 files)
  • Rename theo timestamp: YYYYMMDD_HHMMSS_description.sql
  • Tạo migration registry table để track đã chạy migration nào
  • Script runner check registry trước khi apply
MEDIUM RLS Policy Placeholder

Các policy USING(true) trong migration cũ không có giá trị bảo mật — mọi role đều đọc/ghi mọi row. Multi-tenant isolation dựa hoàn toàn vào WHERE clause trong application code.

Kế hoạch sửa
  • Implement company_id isolation tại service layer trước
  • Sau đó mới enforce RLS với company_id = current_setting(app.company)
  • Test isolation với superAdmin cross-company queries
LOW Console.log Cleanup

Nhiều console.log trong service layer và API routes — một số có thể log dữ liệu nhạy cảm (user info, request body). Cũng gây noise trong production logs.

Kế hoạch sửa
  • ESLint rule: no-console warn trong src/ (trừ lib/logger.ts)
  • Tạo logger.ts với level control (debug/info/warn/error)
  • Grep và replace console.log → logger.debug trong services
LOW camelCase Column Debt

Tên cột trộn camelCase (roleLabel, userId) và snake_case (created_at, updated_at). Raw SQL phải double-quote cột camelCase. Dễ gây lỗi khi thêm cột mới.

Kế hoạch sửa
  • Quy ước mới: tất cả cột mới dùng snake_case
  • Không rename cột cũ (breaking migration risk)
  • Document rõ trong CLAUDE.md danh sách cột camelCase cần quote
