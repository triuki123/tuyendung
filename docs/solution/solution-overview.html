Integration Architecture

4 hệ thống ngoài kết nối sâu vào nghiệp vụ

📧
Zimbra Mail Server
SOAP Admin API · server-side only
  • Tạo / xóa / đình chỉ email account
  • Đặt password, alias, quota
  • Đẩy HTML chữ ký email lên server
  • Xác thực qua admin token SOAP
  • TLS tuỳ chỉnh (ZIMBRA_TLS_REJECT_UNAUTHORIZED)
  • Default suffix password: @123
🕐
ZKTeco / ADMS
HTTP polling · attendance machines
  • Kết nối máy chấm công qua HTTP port 8088
  • Sync dữ liệu check-in/out định kỳ
  • Mapping user ID máy ↔ user DB
  • Tính giờ vào/ra theo rule (T2–T7)
  • Xử lý vắng, trễ, tăng ca tự động
  • Cấu hình nhiều máy qua admin UI
📬
AWS SES + Nodemailer
Transactional email · SMTP relay
  • Gửi email đặt lại mật khẩu
  • Thông báo onboarding link
  • Nhắc gia hạn hợp đồng tự động
  • Cấu hình qua AWS IAM credentials
  • FROM address: SES_FROM_EMAIL env
  • Fallback: Nodemailer SMTP trực tiếp
✈️
Telegram Bot
Webhook · approval · login
  • Nhận thông báo yêu cầu chờ duyệt
  • Duyệt/từ chối ngay trên Telegram
  • Login widget HMAC verify song song email
  • Webhook → gọi nội bộ API có sẵn
  • telegram_id lưu DB (migration 146)
  • Cần /setdomain + NEXT_PUBLIC env
🐘
PostgreSQL
Self-hosted · pg Pool · migrations
  • Truy cập qua db.ts helper: query/queryOne/execute
  • withTransaction cho atomic operations
  • Pool max: PG_POOL_MAX (default 30)
  • 154+ migration files, thứ tự numeric sort
  • Tên cột camelCase cần double-quote trong SQL
  • DATE columns: setTypeParser OID 1082 fix
📡
Server-Sent Events
Realtime · notification bell · live data
  • SSE stream từ API route Next.js
  • Notification bell realtime
  • Push khi ticket/task/approval thay đổi
  • Client dùng EventSource API
  • NotificationContext quản lý state
  • Không cần WebSocket server riêng
🔒

Security Model

Authentication · Authorization · API security · Data protection

🔑
Authentication
  • ● Password hashing: bcryptjs (cost factor 10+)
  • ● Login: POST /api/auth/login → DB verify
  • ● Session cookie HTTP-only (server-side)
  • ● Telegram Login: HMAC-SHA256 verify
  • ● LEGACY: authStore.ts mock users (cần xóa)
  • ● Hai hệ auth song song — cần thống nhất
🛡️
Authorization (RBAC)
  • ● 4 roles: super_admin, admin, manager, user
  • ● Per-module: view/create/edit/delete/approve/export
  • ● Module child kế thừa quyền module cha
  • ● Always-visible modules (không cần quyền)
  • ● ⚠️ x-user-permissions header spoofable (kỹ thuật nợ)
  • ● Cần thay bằng server-side token verify
🔐
API Security
  • ● Permission check tại API route (server-side)
  • ● api-permissions.ts middleware chặn trước DB call
  • ● Input validation trước khi INSERT/UPDATE
  • ● Parameterized SQL queries (chống injection)
  • ● Error message không lộ stack trace ra client
  • ● HTTPS qua Traefik TLS termination
🛡️
Data Protection
  • ● Không hardcode credentials — env variables
  • ● Không log password / data nhạy cảm
  • ● Zimbra credentials server-side only
  • ● DB connection string qua DATABASE_URL env
  • ● PGSSL tuỳ chỉnh (self-signed cert support)
  • ● RLS policy hiện là USING(true) — cần strengthen
⊠

Permission Model

RBAC 4 roles · per-module actions · inheritance · always-visible

👑
super_admin
Toàn quyền hệ thống. Xuyên công ty. Không bị chặn bởi bất kỳ permission check nào.
🔑
admin
Quản trị toàn công ty. Phê duyệt cấp cao. Cấu hình hệ thống trong phạm vi công ty.
👔
manager
Quản lý nhóm/phòng ban. Xem + duyệt scope cấp dưới trực tiếp. Báo cáo giới hạn.
👤
user
Nhân viên thường. Self-service: xem tài sản/hợp đồng của mình, tạo yêu cầu.

ℹ️
Kế Thừa Quyền Module
Module con (ví dụ: hr-recruitment-dashboard) kế thừa permission từ module cha (nguon-nhan-luc) nếu không có override riêng. Quyền mẫu được lưu trong DB và có thể sửa/xóa trực tiếp qua admin UI (migration 116–117). Always-visible modules: Dashboard, Hồ Sơ Cá Nhân — không cần cấu hình quyền, mọi user đã đăng nhập đều thấy.
